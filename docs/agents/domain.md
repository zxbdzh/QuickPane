# 领域文档

本文说明工程技能在探索代码库时应如何读取本仓库的领域文档。

## 开始探索前读取

- 根目录的 **`CONTEXT.md`**；或者
- 如果根目录存在 **`CONTEXT-MAP.md`**，按其中的映射找到各上下文的 `CONTEXT.md`，并阅读与当前主题相关的文件；
- **`docs/adr/`**：阅读与当前工作区域相关的 ADR。对于多上下文仓库，还需检查 `src/<上下文>/docs/adr/` 下的上下文级决策。

如果这些文件不存在，直接继续，不要提示文件缺失，也不要预先建议创建。`/domain-modeling` 技能会在术语或决策真正明确后按需创建它们。

## 文件结构

本仓库采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

## 使用术语表中的词汇

当输出内容涉及领域概念时，例如 Issue 标题、重构建议、假设或测试名称，应使用 `CONTEXT.md` 中定义的术语，不要改用术语表明确排除的同义词。

如果术语表尚未包含所需概念，应先判断是否使用了项目中不存在的语言；若不是，则说明领域文档确有缺口，并将其记录给 `/domain-modeling`。

## 标明与 ADR 的冲突

如果输出内容与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> _此方案与 ADR-0007（订单采用事件溯源）冲突，但值得重新讨论，因为……_
